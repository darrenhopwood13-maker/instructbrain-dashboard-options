## Variant 3: Blueprint grid

### Design stance
The account as **one map you read at a glance and then interrogate**. A list tells you what happened;
a map tells you where the weight is.

### Key choices
- **Layout:** one square per item, arranged by project, by survey type or by week. Regrouping
  re-lays the whole map without leaving the page.
- **Colour:** the states are the palette - Laser Green closed, navy allocated, pale open, orange
  overdue, and a **dashed empty square for an item nobody has assessed**. That last one is the point:
  it is the thing a percentage hides.
- **Ground:** faint blueprint grid, borrowing the motif the product already uses for site drawings.
- **Interaction:** hover any square for the item, click to open a drawer on the real record, **drag
  across a block to select a region** and act on that set together, plus a "needs attention now" list
  underneath that opens the same records.

### Trade-offs
- **Strong at:** answering "where", surviving a glance from across the room, and looking like nothing
  else in construction software. It is also the only variant that stays impressive with one month of
  data, because a map reads as full where a trend line reads as empty.
- **Weak at:** it needs a legend, so it must stay simple. Costs the most to build.

### Best for
The demo. The screen that makes someone say they have not seen that before.
